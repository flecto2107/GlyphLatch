# GlyphLatch

## Установка

Скачайте `GlyphLatch-Setup-*-win-x64.exe` со страницы [релизов GitHub](https://github.com/flecto2107/GlyphLatch/releases). Установщик рассчитан на Windows 11 x64, включает .NET и работает без прав администратора. Ярлык появится в меню «Пуск». Путь по умолчанию — `%LOCALAPPDATA%\Programs\GlyphLatch`.

Для запуска из любой папки скачайте архив `GlyphLatch-Portable-*-win-x64.zip`, распакуйте и откройте `GlyphLatch.exe`. Версия отображается внизу боковой панели.

Перед обновлением или удалением выберите «Выйти из GlyphLatch» в меню трея. При удалении через настройки Windows локальная библиотека и исходные шрифты сохраняются.

## Работа с GlyphLatch

1. Создайте папку кнопкой «+» рядом с разделом «Папки». Выберите её и нажмите «Добавить шрифты…», чтобы добавить ссылки на файлы TTF и OTF. Для файла или папки также работает перетаскивание в окно.
2. Нажмите «Подключить папку…», чтобы добавить каталог с диска. Его название и вложенные папки появятся в боковой панели. GlyphLatch отслеживает изменения подключённых каталогов. Папки и файлы остаются на диске, при удалении папки из библиотеки удаляются её ссылки.
3. Сравнивайте начертания прямо в списке. Кнопки «Латиница», «Кириллица», «Цифры», «Ещё» и «Свой текст» и регулятор размера применяются ко всем видимым строкам. Квадраты обозначают отсутствующие символы. «Глифы» в строке или F4 открывают панель справа. В ней можно искать по символу, коду U+ и идентификатору с префиксом #, просматривать глифы без кода Unicode и копировать доступные символы. В разделе «Активные» показаны временные регистрации GlyphLatch.
4. Нажмите на точку слева от начертания или гарнитуры, чтобы переключить активацию. Серая точка означает выключенное начертание, зелёная лампочка — активную регистрацию, зелёное кольцо — частично включённую гарнитуру. После включения может понадобиться переоткрыть меню шрифтов в редакторе. Результаты проверок есть в [матрице совместимости](docs/compatibility.md).
5. Выберите одно или несколько начертаний через Ctrl или Shift и нажмите «В набор…». Здесь можно пополнить существующий набор или сразу создать новый. Если набор уже открыт, импорт добавляет шрифты прямо в него. Для применения откройте набор и нажмите «Включить набор». Переключение сохраняет общие начертания и ручные включения.
6. Меню «···» рядом с папкой или набором содержит активацию, переименование и удаление из библиотеки. Граница панели слева перетаскивается. Щелчок по гарнитуре раскрывает её начертания. Пункт «Убрать из библиотеки» в строке шрифта исключает его из поиска и наборов. Повторное добавление файла возвращает его в библиотеку.
7. В «Песочнице» выбирайте начертания через поиск над общим макетом и щёлкайте по любому блоку для редактирования. Латиница, кириллица и свой текст сохраняются отдельно. «Сравнить A/B» открывает второй макет с теми же текстом и размерами. Начертания можно выбрать для каждого варианта отдельно. Предпросмотр читает файлы библиотеки без временной регистрации в Windows.

Крестик скрывает окно в трей. Наведите курсор на знак GlyphLatch или щёлкните правой кнопкой, чтобы открыть меню. Команда «Выйти из GlyphLatch» снимает регистрации и завершает процесс. После аварийного закрытия Windows может удерживать шрифт до конца сеанса. Библиотека, тема и настройки образца сохраняются локально в `%LOCALAPPDATA%\GlyphLatch\library.db`.

Ctrl+F открывает поиск, Ctrl+O добавляет файлы, Ctrl+Shift+O подключает папку, Ctrl+Enter переключает активацию выделения. Обоснование решений описано в [разборе интерфейсов](docs/interface-design.md).

Medeo Sans Regular и SemiBold используются для интерфейса, Medeo Mono Regular — для кодов глифов. Эти начертания включены в автономную сборку. [Лицензия Medeo](src/GlyphLatch.Windows/Assets/Fonts/OFL-Medeo.txt)

Сборка установщика и переносимого ZIP из корня проекта. Понадобятся .NET 10 SDK x64, PowerShell и [Inno Setup](https://jrsoftware.org/inno-setup/downloads). При необходимости передайте путь к `ISCC.exe` параметром `-InnoCompiler`.

```powershell
.\tools\build-release.ps1
```

Версия задаётся в `src/GlyphLatch.Windows/GlyphLatch.Windows.csproj` и попадает в приложение, установщик и имена файлов в `artifacts`. К релизу GitHub с тегом `v<версия>` прикладываются установщик и переносимый ZIP.

## Консольный прототип

Этап 0 проверяет, видят ли открытые Windows-приложения временно зарегистрированные локальные шрифты. Прототип рассчитан на Windows 11 x64 и обычную учётную запись. Актуальные результаты собраны в [матрице совместимости](docs/compatibility.md).

## Сборка и системная проверка

Понадобятся .NET 10 SDK x64, PowerShell 7 и Python 3 с FontTools. Выполните из корня проекта в обычном пользовательском сеансе.

```powershell
dotnet build .\src\GlyphLatch.Probe -c Release
python -m pip install fonttools
$manifest = python .\tools\make-probe-fonts.py .\artifacts\fixtures
$probe = '.\src\GlyphLatch.Probe\bin\Release\net10.0-windows\GlyphLatch.Probe.exe'
.\tools\measure-probe.ps1 -Probe $probe -Manifest $manifest
```

Генератор создаёт оригинальные тестовые шрифты с уникальными именами. Статический TTF, статический OTF и вариативный TTF отображают латинскую `A` ромбом. У каждого запуска отдельный манифест с именами семейств и файлов. Проверка сравнивает видимость до включения, после включения, выключения, повторного включения и штатного выхода. GDI и DirectWrite опрашиваются из нового процесса на каждом шаге.

Для проверки принудительного завершения добавьте `-IncludeForcedExit`. Скрипт завершает только созданный им тестовый процесс после подтверждения регистрации, проверяет видимость и запускает новый экземпляр в том же сеансе. Затем он пытается снять одну подтверждённую регистрацию по точному пути и проверяет, виден ли ещё шрифт. Используйте только свежие образцы из генератора и один запуск проверки на манифест.

## Проверка открытого редактора

В Photoshop 27.10.0.26 зафиксирован сбой при создании нового текстового слоя после выключения синтетического TTF. Используйте отдельный тестовый документ. Подробности и результат контрольного прогона есть в [матрице совместимости](docs/compatibility.md).

Возьмите точное имя семейства и имя файла из манифеста. В командах ниже `RUN` обозначает уникальную часть имени файла и семейства.

```powershell
# Второй процесс до включения и после каждой операции
& $probe query 'GLatch RUN TT'

# Отдельная консоль для живой сессии
& $probe session '.\artifacts\fixtures\static-ttf-RUN.ttf' '.\artifacts\activation.txt'
```

1. Убедитесь, что в исходном состоянии оба API возвращают `False`. Откройте новый локальный документ в редакторе и проверьте отсутствие точного имени в его меню шрифтов. Для редактора с онлайн-библиотекой проверьте и её.
2. В живой сессии введите `on`. При успехе прототип напечатает `count` и UTC-время регистрации, которое также сохранится в необязательный файл-маркер. Повторите `query` в отдельном процессе.
3. Проверьте открытое меню, затем переоткройте его при необходимости. Если шрифт появился, выберите его и введите `AAA`. Проверьте, что отображаются три ромба. Запишите время первого наблюдения и действие, после которого появился шрифт.
4. Введите `off`, повторите `query` и проверку в редакторе. Сравните уже оформленный текст и новый текст. Повторите включение, затем выполните `quit` и проверьте видимость ещё раз. `status` показывает состояние регистрации, подтверждённое прототипом.
5. Для отдельного теста перезагрузки используйте свежий образец и заранее запишите имя семейства. После перезагрузки повторите запрос и проверку в редакторе в новом сеансе.

Прототип регистрирует файл по его текущему пути через Win32. Общая временная регистрация действует в рамках сеанса Windows. Штатный выход снимает собственную регистрацию. Проверка в редакторе нужна отдельно от результата Win32. [Временные шрифты Win32](https://learn.microsoft.com/en-us/windows/desktop/gdi/font-installation-and-deletion) · [Обновление коллекции DirectWrite](https://learn.microsoft.com/en-us/windows/win32/api/dwrite/nf-dwrite-idwritefactory-getsystemfontcollection)
